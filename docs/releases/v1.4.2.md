# Tournament Organizer 1.4.2

Released 2026-10-01 · [Download](#download) · [Changelog](../CHANGELOG.md)

Version housekeeping. The app itself is identical to 1.4.1 — this release makes
the version number mean one thing everywhere, so the program, the installer and
the file you downloaded always agree.

## Highlights

- **The app finally says the same version as everything else.** 1.4.1 was not
  valid semver, so build tools read it as `1.4.1` while the app printed
  `1.4.01` in Settings. A single version string in `package.json` now drives the
  UI, the file names, the installer's version resource and the Android build.
- **Android updates work again.** `versionCode` was pinned at `1`, so installing
  this APK over an existing 1.4.x install would have been rejected. It is now
  derived from the version, so it always rises.
- **The version check is stricter.** The guard that exists to catch drift
  accepted `1.4.01` because `1.4.01` matches a plain `x.y.z` pattern. It now
  requires canonical semver, which is the rule that was actually being broken.

## Installation

- **Windows:** run the installer and follow the prompts. It is not code-signed,
  so Windows shows "Unknown publisher" — choose *More info → Run anyway*. If an
  older version is installed, uninstall it first: Windows lists it separately
  and the new installer will not overwrite it cleanly.
- **macOS:** open the disk image and drag the app into Applications. Not
  notarized: the first launch needs right-click → *Open*.
- **Linux:** `chmod +x Tournament-Organizer-1.4.2-linux-x86_64.AppImage` and run it.
- **Android:** install the APK over the previous one. It is signed with the same
  key as earlier versions, so it updates in place and your projects are kept.

## Known limitations

- Installers are **not code-signed** and the macOS app is not notarized.
- Tables scroll inside their own frame on a phone; they are not reshaped into cards.
- Below 320px wide the layout is untested.

## Upgrading

- Existing projects open unchanged; no project file format change in this release.
- To move projects to another machine: `Export → Save .top.json`, then
  `Import / Recovery`.

Released 2026-10-01 · [Download](#download) · [Changelog](../CHANGELOG.md)

A UI-only pass. No feature, behaviour or scope changed — this release fixes how
the app looks and lays out, nothing else.

## Highlights

- **Text stays in its box.** Flex and grid children can now shrink below their
  content, long words break instead of widening a card, and the page itself can
  no longer scroll sideways. Long German translations no longer push the layout
  off the screen.
- **Names wrap instead of disappearing.** A team name cut to `KS Przedmieście…`
  is worse than useless when you are scanning for it; names now wrap and stay
  readable in the bracket, the result-entry cards and the standings.
- **Small screens work properly.** On a phone the page headers stack, the action
  bar wraps instead of scrolling out of reach, Undo/Redo/Save/Settings get their
  own scrollable row, and cards collapse to one column. The foot bar no longer
  scrolls sideways, so the primary action is always under your thumb.
- **The dark theme is finished.** Hover, disabled, selected and ghost states on
  buttons, pills, chips, cards, inputs and scrollbars all read correctly in dark
  mode, instead of the light greys that leaked through.

## Fixes

- The support note was grey on grey in dark mode — it referenced a colour token
  that never existed and fell back to a hard-coded value.
- The drop-down arrow rendered as a large triangle in dark mode, because a CSS
  shorthand was resetting the size and position of its gradient.
- Narrow-screen rules for the card grids and the document preview were being
  silently overridden by the base rules declared later in the stylesheet.

## Known limitations

- Installers are **not code-signed** and the macOS app is not notarized (see
  Installation).
- Tables scroll inside their own frame on a phone; they are not reshaped into
  cards.
- Below 320px wide the layout is untested.
