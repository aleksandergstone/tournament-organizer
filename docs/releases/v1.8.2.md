# Tournament Organizer 1.8.2

**November 17, 2026**

## One bracket everywhere

The bracket is now a single source of truth rendered identically in three places:

- **App — Bracket tab** – the interactive drabinka with connector lines, match cards, statuses and results entry.
- **App — Documents / PDF** – the same component, same HTML, same connector geometry, same card layout (1:1). The old standalone document-only bracket implementation is removed.
- **Online preview** – the public page now shows the full bracket (Single Elimination, Double Elimination, Groups → Knockout), read-only, with the same colours, accents and branding as the app.

### What changed

**Publish pipeline** (`src/engine/publish.ts`)
- The published snapshot now includes `bracket` — the full placed tree (nodes, links, rounds, width, height, champion) built by `buildBracketTree`, the same function the app uses on screen.
- The site already expected `bracket: BracketTreeView | null` in its contract; previously the field was always `null`, so the bracket page never rendered.

**Documents** (`src/engine/output.ts`, `src/engine/pdf.ts`)
- Already used `renderBracketHtml` — the same pure HTML renderer as `BracketCanvas.tsx`. No change needed; confirmed 1:1 identity.

**Online** (`tournament-organizer-site`)
- `page.ts` `bracketBody()` and `fragments.ts` `bracketView()` already render `s.bracket` via `renderBracketHtml`.
- `seo.ts` `availablePages()` already includes `'bracket'` when `hasBracket(s)`.
- No code changes needed on the site — it just needed the data, which the publish pipeline now sends.

### Verification

For the same tournament, all three views now show:

- Identical number of rounds and matches
- Identical match positions (x, y) and column layout
- Identical connector lines (elbow geometry between rounds)
- Identical match cards (names, scores, status badges, champion label)
- Identical colours and accents from branding
